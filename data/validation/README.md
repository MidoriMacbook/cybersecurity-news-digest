# Проверочные входные данные

`expanded.json` и `expanded.csv` содержат один расширенный **синтетический** набор из девяти записей: кириллица и UTF-8, пустые поля, повтор ID с другим URL, HTML, переносы строк, длинный текст, даты с часовым поясом и без него. Это учебные материалы, а не фактический набор организаторов. Исходные файлы не изменяются при проверке.

Запуск из корня проекта после установки зависимостей:

```sh
python scripts/validate_contest.py
python scripts/validate_contest.py --base-url https://cybersecurity-news-digest-clean.onrender.com --output artifacts/validation-public
python -m pytest scripts/tests -q
```

Основной запуск сохраняет 18 отдельных обязательных сценариев, дополнительные проверки JSON/CSV и `artifacts/validation/summary.json`. Каталог каждого сценария содержит `input.json`, `response.json`, `result.json`, `verdict.json`; verdict перечисляет expected, actual, passed, время и доступные версии. Ошибки запросов и исключения дают неуспешный verdict. Для HTTP-ошибок до генерации версии модели и промпта отсутствуют по указанной причине.

Внешние обращения к модели в проверках ошибок **заменены локальным транспортом**. Такие сценарии всегда выполняются внутри процесса, даже при `--base-url`, и помечены `simulated_provider: true`, `live_ai_tested: false`. Они не подтверждают работу реального провайдера или его конфигурацию в публичном сервисе. Секретный ключ для запуска не требуется.

Фактический набор организаторов пока отсутствует. Когда он будет предоставлен, сохраните исходный JSON/CSV отдельно без редактирования, затем загрузите файл на странице создания дайджеста. Выберите контрольное время с часовым поясом, дождитесь результата и сохраните JSON результата и CSV журнала. Сверьте число строк, даты, причины исключения, подтверждающие фрагменты и исходные записи с оригиналом. Не добавляйте персональные данные или секреты в публичный репозиторий. Успешная синтетическая проверка не заменяет такой прогон.

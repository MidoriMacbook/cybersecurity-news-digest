# Работа ИИ и происхождение фактов

В основном API используется редакционный промпт `editorial_v2.json`. После независимой проверки метаданных, периода и достаточности текста модель получает eligible_articles и safe_fragments. Публикации обозначены как недоверенные данные.

Системные правила запрещают выполнять инструкции из статьи, раскрывать системный промпт, менять задачу, адресатов или настройки и добавлять факты. Оговорки, предварительный статус и противоречия должны сохраняться. XML/JSON-разделение само по себе не защищает от injection: решающая проверка выполняется сервером.

Ответ запрашивается как строгий JSON по схеме EditorialPlan. Для каждого допустимого материала модель возвращает relevant и подтверждающий Evidence. Группы содержат source_ids, lead, priority и ranking_evidence. Модель выбирает тему, объединение, порядок и ведущие предложения; текст составляется из проверенных предложений источников. Файлы relevance_v1, grouping_v1, ranking_v1, digest_v1 и post_v1 сохранены как исходные материалы разработки, но основной API не вызывает их отдельно. extraction_v1 используется дополнительным адаптером проверки цитат и его regression tests.

Сервер сравнивает каждый Evidence с собственным безопасным извлечением, проверяет source_id и URL. Все допустимые ID должны получить ровно одно решение. Релевантные ID должны образовывать полное разбиение по группам. Известные повторные сообщения нельзя разделять или частично исключать. Разные CVE, включая идентификаторы в заголовках, нельзя объединять. Факты, числа, оговорки, подтверждения и опровержения сохраняются независимо от ведущего предложения.

Внешний запрос имеет ограничение тела ответа 1 МБ и deadline 12 секунд на попытку. Допускается две попытки; вход модели ограничен 180 КБ. Ошибка поставщика, схемы или правил сохраняет локальный результат с предупреждением. Подключение задаётся LLM_API_KEY, LLM_BASE_URL и LLM_MODEL только на backend. Настройки: max_completion_tokens=8000 и строгая json_schema; остальные параметры по умолчанию поставщика.

В результат записываются план, попытки, модель, версия поставщика (если есть), промпт и время. Без usage токены не считаются нулевыми затратами: token_usage_available=false. Стоимость без тарификации остаётся null. Повторная серверная проверка воспроизводит сохранённый план и факты, не вызывает модель заново.

Обоснование оценки состоит из вычисленных факторов и не использует позицию в поиске. Поиск в приложении не реализован: RSS/HTML preview — прямой запрос по пользовательскому URL; журнал сохраняет обращение к источнику. Не утверждайте наличие поисковой выдачи или её аудита.

Семантическая оценка релевантности и объединения остаётся оценкой модели. Экстрактивное совпадение не доказывает истинность текста источника. Полноценный пересказ своими словами и автоматический перевод не реализованы. Адаптер проверен имитированными валидными и ошибочными ответами; живой LLM без предоставленного ключа не запускался. Метрики отражают фактические обращения приложения к модели.

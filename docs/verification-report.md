# Отчёт проверок

Дата: 15 октября 2026. За основу принят предоставленный архив; старой Git-истории в новой рабочей копии нет.

## Очистка

В публичный проект не перенесены локальная SQLite-база, .env.local, вложенные архивы, результаты личных запусков, внутренние отчёты и инструкции, служебные планы и ранее собранные файлы. Сохранены исходники, тесты, синтетические наборы, инструкции запуска и конфигурация публикации. Поиск шаблонов ключей не обнаружил совпадений в принятом исходном архиве. Локальный файл окружения содержал только адрес API; он исключён из публичной копии.

## Подтверждённые проверки

- Исходная версия: 63 backend-теста, Ruff и mypy прошли.
- Четыре добавленных регрессионных теста первоначально воспроизвели ошибки: отрицание затронутости системы, смешение исследователя с пострадавшей организацией, дата окончания поддержки как дата события, необработанная ошибка хранилища.
- После исправлений: 68 backend-тестов прошли, включая добавленную проверку старта в контейнере. Ошибка хранилища возвращает безопасный HTTP 503 без connection string.
- Frontend: 20 тестов, TypeScript, ESLint, Prettier и production build прошли; сформированы пять статических страниц.
- Ruff, проверка форматирования и mypy прошли. Последние проверки GitHub Actions для версии 5a31b3d: Tests, Lint и сборочный workflow Deploy завершились успешно.
- Реальные платные запросы без ключа не выполнялись. В тестах используются имитированные ответы модели.
- Frontend-команды CI выполняются в apps/web, где находится packageManager. Docker получает pnpm-workspace.yaml до установки зависимостей.

Есть предупреждение устаревания интерфейса Starlette TestClient с httpx; оно не является провалом тестов.

## Исправленные проблемы

- В новую историю не перенесены прежние коммиты и локальные результаты запусков.
- Автор и коммиттер настроены на аккаунт владельца с приватным GitHub email.
- Устранены внутренние названия и абсолютные пути среды в публичных файлах и браузерных скриптах.
- Frontend CI запускает pnpm из каталога с packageManager; Docker копирует workspace-конфигурацию до установки зависимостей.
- Отрицание затронутости не превращается в поражённую систему; исследователь не считается жертвой; окончание поддержки не считается датой атаки.
- Ошибка SQLAlchemy возвращает безопасный 503.
- Исправлено вычисление DEMO_DATA_DIR при старте контейнера.

## Обновление, повторный деплой и смена ключа

Обновление: git pull --ff-only, изменения, тесты/lint/typecheck/build, commit от имени владельца, push main. В панели Render выберите Manual Deploy → Deploy latest commit, дождитесь Live, проверьте /health и новый демо-выпуск. Перед деплоем экспортируйте нужную историю.

Смена ключа: Render → сервис → Environment → LLM_API_KEY; при необходимости обновите LLM_BASE_URL/LLM_MODEL и сохраните с перезапуском. Ключ хранится только на backend. Успех проверьте новым выпуском с включённым ИИ по фактическому режиму, модели и попыткам. Старый раскрытый ключ отзывается у поставщика. Подробности — в deployment.md.

## Практические ограничения

Текст остаётся экстрактивным. Сопоставление цитаты с источником не устанавливает истинность новости или подлинность загруженных метаданных. Группировка и обнаружение противоречий консервативны; неизвестные роли и даты остаются пустыми. Автоматического перевода нет. Внешняя PostgreSQL и платный API модели пока не проверялись. Письмо является предпросмотром; автоматической отправки нет.

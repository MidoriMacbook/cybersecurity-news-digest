## Найдено и исправлено

Главная знала только о конфигурации ключа и не помнила факт принятия AI. Добавлены две технические записи в существующую БД, безопасный публичный статус и его обновление в UI. Устранено ложное обновление статуса при скрытом idempotency replay. Публичный status не выдаёт ID чужих выпусков.

Два реальных предварительных прогона на 1.6.1 показали отклонение пересказа. В 1.6.2 повтор требует дословных evidence; статический код причины помогает отличить пропущенный факт от чужой лексики. Grounding, схема, семантическая сверка, fallback и лимиты не ослаблены. Новые тесты воспроизвели ошибки до исправления.

## Ограничения сдачи

1. Реальный принятый AI доказан на коротком фрагменте одной новости; два реальных материала получили HTTP 429. Стабильная обработка пяти реальных событий и данных организаторов не доказана.
2. Grounding консервативен и отклоняет часть допустимых пересказов. Вероятностная сверка той же моделью не является независимым фактчекингом.
3. Render Free может засыпать; после потери SQLite подтверждение исчезнет. Не проверены внешняя PostgreSQL, distributed concurrency и production load.
4. Публичная демонстрация без аутентификации предназначена для открытых материалов. Почта автоматически не отправляется.

История проверок предыдущих версий сохранена в Git, [presentation-report.md](presentation-report.md) и [bugfix-report.md](bugfix-report.md). Старые утверждения об отсутствии ключа не описывают текущий сервер. Полная готовность на неизвестных конкурсных данных не заявляется.

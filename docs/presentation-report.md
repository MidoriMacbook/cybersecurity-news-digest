## 6–8. Неподтверждённое и фактический режим

Реальный AI не запускался: у владельца нет ключа. Его не запрашивали и не подменяли фиктивной конфигурацией. Публичный сервер: `mode=mock`, `llm_configured=false`, модель `extractive-local`, промпт `pipeline-v1`, версия 1.6. Новый keyless-выпуск содержит `mode=mock`, `llm_attempts=0`; неизвестный usage — `null`.

Фактические качество/совместимость провайдера, реальные usage и prompt injection, набор организаторов, первичное происхождение источников и production-нагрузка остаются неподтверждёнными. Приоритет основного источника эвристический; отдельная семантическая сверка использует ту же модель.

## 9. Будущий ключ

Render → backend → Environment: настроить `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL`, перезапустить, включить «Использовать ИИ», проверить health и **новый** выпуск. Проверить `mode=ai`, фактические модель/версию/промпт, обращения, usage и факты. После использования удалить/заменить ключ и при необходимости отозвать у поставщика. [Все десять шагов](deployment.md#подключение-модели-после-получения-ключа). Изменение frontend не нужно, но совместимость конкретного API ещё требует реального теста.

## 17. Остаточные риски

Render Free засыпает; SQLite и файлы контейнера непостоянны. Автоматический webhook после push пока не подтверждён: workflow Deploy без hook проверяет сборку, а Live и точный SHA проверяются отдельно. Публичный сервис без аутентификации не предназначен для конфиденциальных материалов. Локальная обработка консервативна и не является ИИ; модельная семантическая проверка не доказывает истинность входного источника. Полная конкурсная готовность не заявляется.

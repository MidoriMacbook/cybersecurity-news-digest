# Безопасность

API-ключ хранится в LLM_API_KEY на сервере. Файлы .env и локальные базы исключены из Git. Не помещайте ключ в NEXT_PUBLIC_*: эти переменные видны браузеру. Не передавайте ключи через news text, URL или выгрузки.

Публикации — недоверенные данные. Система не выполняет содержащиеся в них команды, не меняет адресатов и не отправляет письмо. Внешний текст структурно отделён от инструкций модели; ответ проверяется схемой и наличием подтверждающих фрагментов. Это защита на нескольких уровнях, а не обещание идеального детектора injection.

Сбор RSS/HTML ограничен разрешёнными доменами SOURCE_ALLOWED_HOSTS. Backend проверяет публичность адресов, не следует redirects, ограничивает время, размер ответа и число источников. Добавляйте только доверенные публичные источники; private, loopback, link-local и reserved адреса запрещены. Не включайте домены внутренних сервисов. Недоступный источник записывается в журнал, остальные продолжают обрабатываться.

Форма и API ограничивают объём входа и количество материалов. Серверные ограничения и rate limits защищают демо от обычного злоупотребления; production требует внешнего reverse proxy, централизованных quotas и очереди заданий.

HTML источников преобразуется в текст, React экранирует его. Письмо создаётся из экранированных данных и показывается в sandboxed iframe без скриптов. CSV защищён от интерпретации ячеек как формул. Ссылки ограничены HTTP/HTTPS и открываются безопасно.

Публичная установка не является защищённым хранилищем частных новостей. Идентификаторы результатов не заменяют полноценную аутентификацию и разграничение доступа. Не загружайте персональные данные, корпоративные секреты или закрытые инциденты. Для production добавьте аккаунты, авторизацию каждого результата, retention/delete policy, шифрование, резервные копии и мониторинг.

При смене ключа измените LLM_API_KEY в окружении backend, перезапустите сервис и проверьте /health и метаданные прогона. При утечке сначала отзовите ключ у поставщика, затем выпустите новый; удаление строки из Git не отменяет компрометацию.

Сообщайте об уязвимостях владельцу репозитория приватным способом. Не публикуйте секреты в issues. Дайджест информационный, не официальная рекомендация.
